# T1.6 — Port the laser app's compile chain onto the shim

**Phase 1 · Effort 1–2 d · Depends: T1.5 · Gated by: —**
**Invariants:** dual-build; size ±10 %. Index: `../PORT_PLAN_STEPS.md` · Layout: `../refs/component-layout.md`

## Goal
The laser app's full source set compiles on the shim — no module refactoring yet.

## Actions (source moves → components)
- `components/uc2_core/` ← `main/src/{state,config,qid,message,buzzer}` (gated:
  `UC2_MESSAGE_CONTROLLER` etc. per `main/CMakeLists.txt` logic).
- `components/uc2_serial/` ← `main/src/serial` (SerialProcess 28 KB, SerialProtocol 19 KB,
  Endpoints).
- `components/uc2_io/` ← `main/src/{digitalin,digitalout,analogin,analogout,encoder}`
  (laser needs digital-in).
- `components/uc2_canopen/` ← `main/src/canopen` **laser-relevant subset only**
  (NODE_ROLE=2 laser node: OD via `uc2_od`, SDO/TPDO; no OTA-sender, no DeviceRouter
  dispatch paths the laser doesn't compile) — gate the rest off via Kconfig; the full
  file set lands as later boards need it.
- `components/uc2_app/` keeps `main.cpp` (setup/loop) as the app entry glue.

## Rules (important)
- Fix per-file compile errors by **extending `uc2_hal`** (new Arduino APIs discovered →
  add to shim + table in `../refs/hal-shim.md`), NOT by refactoring modules.
- Do not change protocol bytes or control logic — this is a compile-level port.
- `#include "PinConfig.h"` resolves via the app's include dir (T1.5).

## Commands
```bash
cd apps/canopen_slave_laser && ./build.sh
pio run -e UC2_canopen_slave_laser_release    # dual-build invariant
make test
```

- PIO laser env still green; `make test` green.
