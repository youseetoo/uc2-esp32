# T3.3 — Port `uc2_bt` onto IDF BT

**Phase 3 · Effort 3–5 d · Depends: T3.2 · Gated by: D2**
**Invariants:** IDF-only (no PIO); size/RAM band vs baselines. Index: `../PORT_PLAN_STEPS.md`

## Goal
The BT controller layer compiles and works on IDF Bluedroid classic (per `DOCS/bt.md`),
still C++ (Phase 4 C-ifies it in T4.5).

## Context
- Sources: `main/src/bt/` — `BtController.cpp` (34 KB), `HidController.cpp` (19 KB),
  `esp_hid_gap.c` (30 KB, C — move nearly verbatim), `HidGamePad.h`,
  `PS4TrackpadParser.h`; vendor `lib/PSController` (C++ leaf, D2).
- Gate: `UC2_BLUETOOTH` (component registration), `UC2_BTHID` (HID-specific sources).

## Actions
1. `git mv main/src/bt components/uc2_bt/` (+ PSController into `components/` per T1.2
   symlink rule if not done).
2. Rewrite the Arduino/ArduinoBT seams: `esp_hid_gap.c` → Bluedroid GAP/HID API
   (BDA, `BT_HID` callbacks); `BtController` pairing/scan/connect state machine stays,
   only its transport calls change; PS4 HID report encoding untouched.
3. BT sdkconfig fragment from `DOCS/bt.md` lands in the **BT apps'** `sdkconfig.defaults`
   only (never root).
4. Compile for one BT app first (pick `apps/uc2_3` when T3.4 creates it, or a scratch BT
   app if T3.4 is later — orchestrator's call; keep this step's app minimal).
