# T3.2 — Pick the BT stack; write `DOCS/bt.md` (D2)

**Phase 3 · Effort 1–2 d · Depends: T3.1 · Gated by: D2 (C++-leaf tolerance — Bluedroid classic-only needs fewer C++ seams), D1 (IDF version)**

## Goal
A written, evidence-backed BT stack decision for the IDF apps.

## Recommendation (plan's default)
**Bluedroid, classic (BR/EDR) only, HID device profile** — matches the field behavior
(`UC2_FORCE_BT_CLASSIC_ONLY` already on the master), smallest RAM footprint of a working
BT stack, and `esp_hid_gap.c` (already C) maps onto Bluedroid's GAP/HID APIs directly.
NimBLE is the fallback **only** if T3.1 shows the code actually uses BLE (inventory will
say so explicitly); if it does, the decision flips to "Bluedroid for classic boards +
document the BLE subset" and T3.3 scope grows.
