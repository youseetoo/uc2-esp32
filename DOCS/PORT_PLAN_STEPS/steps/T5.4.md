# T5.4 — M5GFX boards: record the PIO-only decision (D4)

**Phase 5 · Effort 0.5 d · Depends: T4.7 · Gated by: — (D4 confirmed 2026-10-08 = option (b): keep on PIO)**
**The decision is made: `m5stack_dial` + `waveshare_d7` (7") stay on PIO** until a later
port. Options (a)/(c) below are retained for that later port's planning.
**Invariants:** dual-build until the boards are cut over. Index: `../PORT_PLAN_STEPS.md`

## Goal
Resolve what happens to the M5GFX-dependent envs: `m5stack_dial`, `m5stack_dial7`,
`waveshare_d7`.

## Options (present to user)
- **(a) Port to esp_lcd + LVGL-free drawing**: rewrite the small M5GFX usage surface
  (the dial UIs) on `esp_lcd` (SPI QSPI panels) — most work, full C end state.
- **(b) Keep those 3 boards on PIO** until a later project: they stay in
  `build-and-release.yaml`'s PIO matrix, get no IDF app; the port is "17 CI envs →
  14 IDF apps + 3 PIO-only boards". Lowest risk.
- **(c) esp_lcd + M5GFX-as-C++-leaf**: run M5GFX on ESP-IDF (it supports IDF builds)
  as a documented C++ exception.

**Recommendation: (b)** — the dial/7" boards are secondary; (a) is a UI port of its own.
The dial *controller* (M5GFX-free, `uc2_dial`) already works in `canopen_master` (T3.5),
so no capability is lost.

## Actions (execute (b); (a)/(c) are the later port's options)
- **(b) — do now**: record the decision in `DOCS/m5gfx.md` (the 3 M5GFX envs stay on
  PIO; options (a)/(c) documented for the later port); mark the 3 envs "PIO-only" in
  `DOCS/boards.md` + the `refs/env-app-mapping.md` §1 note; no code work.
- (a) later: create `apps/m5stack_dial`, `apps/m5stack_dial7`, `apps/waveshare_d7`; esp_lcd
  panel config from `main/config/m5stack_dial*/` (QSPI pins); port the dial UI; `[HW]`
  smoke.
- (c) later: vendor M5GFX, IDF build flags, `[HW]` smoke.

## Acceptance
- Decision recorded; the 3 envs' status is unambiguous in `DOCS/boards.md` (or
  `refs/env-app-mapping.md` §1 note); CI reflects the choice.

## Rollback
(b) is the safe default; (a)/(c) each revert to (b).
