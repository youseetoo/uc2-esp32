# T3.7 — `[HW]` PS4 pairing/trackpad + RAM headroom verification (all BT boards)

**Phase 3 · Effort 2 d · Depends: T3.4, T3.5, T3.6 · Gated by: D2**
**Invariants:** this is the Phase-3 hardware gate; results gate T3.8/T4.x BT work. Index: `../PORT_PLAN_STEPS.md`

## Goal
Prove the Bluedroid classic port is behaviorally identical to the PIO binaries on every BT
board, under worst-case PS4 load, within the T3.1 RAM bands.

## Actions (per BT board: UC2_2/3/4/WEMOS, canopen_master, canopen_standalone_v4)
1. **Pairing**: factory-pair a DS4 (or re-pair existing); confirm HID device shows as the
   same product/VID-PID identity the app declares.
2. **Trackpad + buttons**: full event matrix — every button, both sticks, trackpad scroll
   — compared against the T0.4 baseline serial transcripts (`{"task":"/get_state"}` key
   set + act round-trips).
3. **Worst-case soak**: 30 min with PS4 connected, motor jogging, LEDs animating,
   laser cycled: internal DRAM free stays inside the T3.1 band; no BT disconnects, no
   watchdog.
4. **Reconnect test**: unplug/replug PS4 10× — pairing state survives, no RAM leak
   (free-heap drift < 1 %).
5. Record per-board results in `DOCS/baselines.md`.

## Acceptance
- All 6 BT boards pass items 1–4 within bands; results committed.
- Any band breach → re-open T3.2 with the data (designed escalation).

## Rollback
Doc/flash-level; no source changes expected in this step (if any are needed, they land as
their own commits with their own re-smoke).
