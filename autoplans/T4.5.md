# T4.5 — C-ify uc2_bt (BtController + HidController + PSController leaf decision)

## Context
uc2_canopen is fully C-ified (T4.4 complete, commit 8abd3a5). This step converts the Bluetooth
controller layer. The PSController library (components/pscontroller) is an external dependency
whose C++-ness drives the architecture of this step — it must be decided first (D2).

## D2 — PSController leaf decision (MUST DECIDE FIRST)
Before any code changes, confirm the PSController approach with the user:
- **Option (a): C-ify PSController too** — convert components/pscontroller to C. This is the
  cleanest long-term result but is a substantial effort (the library wraps L2CAP/BTM/BTDM
  Bluedroid calls).
- **Option (b): Keep PSController as C++** — leave components/pscontroller as-is. BtController
  becomes C, but retains C++ shims for the PSController path (similar to the T4.4 island
  pattern). This is faster and lower-risk, matching the precedent set when HidController
  was left C++ in T4.2.
- **Recommendation: Option (b)** — keep PSController C++. The BT layer already has an
  extern "C" shim layer; the PSController path can stay behind those shims. This minimizes
  risk and aligns with the D1 precedent (HidController stayed C++ when BtController was C-ified).

## Step 4b — C-ify BtController
**Action:** Convert components/uc2_bt/BtController.cpp → BtController.c.
- Replace the `namespace BtController` wrapper with a C API following the T4.4 pattern.
- Keep the existing extern "C" shim functions (bt_setMacAndConnect, bt_scanForDevices, etc.)
  as the primary API — callers already use them.
- Handle PSController path:
  - If D2=(a): convert PSController calls to C equivalents.
  - If D2=(b): wrap PSController calls in the C file with appropriate `extern "C"` or
    include the PSController header conditionally.
- Handle HID path: wrap HidController calls similarly (HidController is C-ified in step 4c).
- The `#ifdef UNIT_TEST` guard that undefines BTHID must be preserved for host tests.
- Move the `processTrackpadData` function (currently static in the namespace) to module level.
- Handle the `lastData` GamePadData struct — make it a file-scope static variable.
- Handle event callback function pointers — use `void *` or function pointer typedefs in C.
- Handle the `#include <cmath>` dependency — use `sqrt()` from `math.h` in C.

**Verification:**
- Host tests: `powershell -File test/unity/run_tests.ps1` → 92 Tests, 0 Failures, 2 Ignored — OK.
- Device builds: cd into each of canopen_master, canopen_slave_motor, canopen_slave_gpio,
  canopen_slave_accelmotor → `C:\Espressif\tools\idf-exe\1.0.3\idf.py.exe build` →
  "Project build complete".
- BtController.cpp deleted, BtController.c exists and compiles.

**Time estimate:** 1-2 hours (depending on D2 decision).

## Step 4c — C-ify HidController
**Action:** Convert components/uc2_bt/HidController.cpp → HidController.c.
- This file uses heavy ESP-IDF HID host APIs (esp_hidh_* functions).
- The C conversion is straightforward — replace C++ types with C equivalents.
- `esp_hidh_event_t` is already an enum.
- `esp_hidh_event_data_t` is a union — already C-compatible.
- `esp_hidh_dev_t` is opaque — already C-compatible.
- Handle `ESP_LOGI/ESP_LOGD/ESP_LOGE` macros — these work in C.
- Handle `std::abs` → `abs()` from `stdlib.h`.
- Handle `sqrt()` — use `math.h`.
- Update CMakeLists.txt to list HidController.c instead of HidController.cpp.

**Verification:** Same as step 4b (host tests + all 4 device builds).

**Time estimate:** 45 minutes - 1.5 hours.

## Risks
1. **PSController dependency:** If D2=(a), the effort is much larger and riskier.
2. **HID host API complexity:** The HidController uses many ESP-IDF HID host functions that
   may have C++-specific features.
3. **Host test compatibility:** The `#ifdef UNIT_TEST` guards must be carefully preserved.
4. **Memory constraints:** The BT stack has specific memory requirements — changes to the
   initialization sequence could affect this.

## Rollback
If a step fails verification:
- Revert the specific file(s) changed in that step.
- Do not proceed to subsequent steps until verification passes.
- If the C conversion of a specific file is problematic, consider leaving it C++ (as was done
  for HidController in T4.2) and documenting the reason.
