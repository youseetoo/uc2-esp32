## Goal
`build-and-release.yaml` gains an `idf-build` job (laser app only) on the same triggers;
release/mirror jobs untouched (still consume PIO artifacts).

## Actions
1. New job in `.github/workflows/build-and-release.yaml`:
   - Triggers: same as existing (pull_request + push to main + tags + dispatch).
   - Checkout with submodules recursive.
   - **IDF setup (pick here, pin the version)**: self-hosted runner/container with IDF
     (per D1; 6.1 at a fixed path) + ccache, or the `espressif/setup-espressif` action
     with the exact version pinned; cache `~/.espressif` and per-app `build/` dirs.
   - Build: `idf.py -D IDF_TARGET=esp32s3 -D PROJECT_DIR=apps/canopen_slave_laser build`.
   - Artifact: `idf-fw-canopen-slave-laser` (app + bootloader + partitions bins).
   - Matrix: `app: [canopen_slave_laser]`, `target: [esp32s3]`, `fail-fast: false`.
2. Also land the `host-tests` job (`make test`) if not added in T0.5.

## Acceptance

  is still produced by the PIO path only.
