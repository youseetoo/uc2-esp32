# T5.4 — M5Stack Dial IDF Port

**Status:** COMPLETE (2026-11-05)

## Summary
Ported M5Stack Dial board from PlatformIO to ESP-IDF 6.1 as a C++ leaf (D4 decision).
Board uses M5GFX display stack + ESP32Encoder C API for reliable encoder handling.
CANopen ORIGINATOR node (NODE_ROLE=2) that writes expedited SDOs directly.

## Files Modified

### apps/m5stack_dial/main/pinconfig.c (NEW)
- Pure-C board pin configuration using `PINCONFIG_DEFAULTS_FIELDS` + overrides
- Only overrides fields that differ from defaults (CAN pins, routing, WiFi)
- Uses GPIO_NUM_2 (CAN_TX) and GPIO_NUM_1 (CAN_RX) for Grove connector

### components/uc2_dial/dial/DialController.cpp (FIXED)
- Fixed encoder rotation handling in `loop()` — was reading encoder position
  but not calculating delta or calling handleEncoderChange
- Now uses `esp32encoder_get_count(&encoder)` to read PCNT counter, calculates
  delta from `lastEncoderPos`, and calls `handleEncoderChange(delta)`
- Removed unused `detents` variable and broken logic

### apps/m5stack_dial/main/CMakeLists.txt (UPDATED)
- Added `-Wno-override-init` to suppress GCC 15 -Woverride-init errors when
  re-initializing fields after `PINCONFIG_DEFAULTS_FIELDS`

### apps/m5stack_dial/CMakeLists.txt (UPDATED)
- Added `main` to `_uc2_proj_comps` list so `libmain.a` (containing `pinConfig`
  definition) is included in the `--start-group/--end-group` linker wrapper
- Added `-Wno-override-init` at project level

## Key Design Decisions
1. **Encoder handling:** Use ESP32Encoder C API (PCNT-backed) instead of M5Dial's
   built-in encoder (which silently degrades to polling on GPIO > 39)
2. **CANopen role:** ORIGINATOR (NODE_ROLE=2) — writes SDOs directly, no master needed
3. **Pin config model:** Pure-C `pinconfig.c` with `PINCONFIG_DEFAULTS_FIELDS` + overrides
   (same pattern as canopen_master)
