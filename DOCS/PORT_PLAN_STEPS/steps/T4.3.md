# T4.3 — C-ify `uc2_motor` (FocusMotor/homing/stage scan) + `Ws2812Rmt`

**Phase 4 · Effort 2–3 d · Depends: T4.1 · Gated by: D2 (FAS/TMC stay leaves; only the
first-party motor code converts)**
**Invariants:** IDF-only (no PIO); size ±10 %; **step timing unchanged** (T2.7 trace is the
reference). Conversion rules: see T4.1.md. Index: `../PORT_PLAN_STEPS.md`

## Sources
- `components/uc2_motor/`: `FocusMotor` (~57 KB — the central motor controller; wraps the
  FAS/AccelStepper backend), `MotorJsonParser`, `MotorGamePad`, `FAccelStep` (thin FAS
  wrapper), `AccelStep`, `StageScan`, `FocusScan`, `MotorTypes`; `main/src/home`
  (HomeMotor); `pid/` + `axis/` (if not already in T4.1).
- `components/uc2_led/Ws2812Rmt.{cpp,h}` — first-party bare-metal RMT driver, **C-ify
  without touching the RMT channel/IRQ layout** (chip-specific struct tables stay).

## ⚠ Timing-sensitive
FocusMotor drives FAS (C++ leaf) from ISR context. The C conversion must preserve:
ISR-safe access patterns, the shared-RMT-IRQ ownership contract (FAS owns the IRQ),
and the step-timing behavior proven in T2.7. Convert, then re-run the T2.7 `[HW]`
timing check on `canopen_slave_motor` before declaring done.

## Actions
1. Convert `MotorTypes`, `MotorJsonParser` first (low risk).
2. Convert `Ws2812Rmt` (small, mechanical) — verify WS2812 boards still render
   identically (T2.1 board or waveshare, whichever is on the bench).
3. Convert `FocusMotor` — keep the class's public method names as `focus_motor_*`
   functions; update the (still-C++) `FAccelStep` wrapper's includes.
4. Convert `StageScan`/`FocusScan`/`HomeMotor` (`test_stage_scan*` host tests cover
   stage scan — must stay green).
5. Re-run T2.7 `[HW]` timing check; re-smoke a WS2812 board.
