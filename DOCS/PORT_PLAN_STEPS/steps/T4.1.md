# T4.1 — C-ify leaf math/state: `pid/ axis/ signal/ state/ config/`

**Phase 4 · Effort 1–2 d · Depends: T3.8 · Gated by: D2 (option (a) = everything C, incl. leaves; (b) = C core, leaves stay C++)**
**Invariants:** IDF-only (no PIO); size ±10 %; protocol bytes unchanged. Index: `../PORT_PLAN_STEPS.md`

## Conversion rules (apply to all of Phase 4 — included here so this file is self-contained)
1. **C99/C11**, no exceptions, no RTTI, no `new`/`delete` (static allocation or
   `heap_caps_malloc(MALLOC_CAP_INTERNAL, …)` for ISR-referenced state).
2. Class → `typedef struct { … } X_t;` + `X_init/X_start/X_stop/X_read/…` functions;
   virtuals → explicit function-pointer tables only where real polymorphism exists.
3. `Arduino.h`/Arduino API → **direct IDF driver calls** (T1.3 converted `main/` with no
   shim; this phase removes the remaining Arduino API usage from the C++ modules it converts).
4. Keep public header names/APIs stable (`pid.h`, `stage_scan.h`, …) so C++ callers
   (not yet converted) compile unchanged against the C headers.
5. `String`/`log_i/log_w` → `char[]` buffers + `ESP_LOG*`; cJSON calls unchanged.
6. Behavior invariants: protocol bytes, JSON key sets, timing — no "improvements" in this
   phase. Any behavior change = separate, explicitly discussed commit.
7. Every commit: `make test` green, all affected `idf.py build`s green.

## T4.1 final file: `led/LedController` (1384 lines) — D2 decision + design

**D2 = (a) everything C.** Rationale: every other first-party file in the component
tree is already C (SignalController.c, QidRegistry.c, State.c, PidController.c,
LaserController.c, …); vendor C++ libs (Adafruit_NeoPixel/DotStar/Protomatter)
stay behind the established thin C++-shim pattern (`signal_neopixel_c.cpp`).
LedController is the last C++ first-party file in T4.1 scope.

### C++ surface to remove (mapped 2026-07, full file)
- `namespace LedController { … }` → C file `LedController.c`, functions prefixed `led_`
  (led_setup/led_loop/led_act/led_get/led_turn_off/led_fill_all/led_set_single/
  led_fill_halves/led_draw_rings/led_draw_circle/led_parse_command/led_exec_command/
  led_set_mode/led_set_pattern/led_set_pixels/led_circle_changed_event/
  led_set_pixel_xy/led_xy_to_index/led_fill_halves_ring_segments/
  led_draw_illumination_rings/led_draw_illumination_ring_segment).
- `enum class LedMode` → C enum `LedMode { LM_OFF=0, LM_FILL, LM_SINGLE, LM_HALVES,
  LM_RINGS, LM_CIRCLE, LM_ARRAY, LM_STATUS, LM_UNKNOWN }` (values unchanged, LDC-001 pins them).
  `LedForStatus`/`LedModes` are already plain C enums. `LedCommand` struct unchanged (17 B packed).
- `String`/`UString` (file-local stand-in, lines 69–78) → plain `strcmp` on
  `valuestring` + tiny `str_lower_into()` helper; `String` concat → `snprintf`.
- `Serial.println` (Uart0Serial stand-in) → `printf` wrapper (all under `#ifndef UNIT_TEST`).
- `millis()/delay()` static inlines → keep (pure C already).
- `random()` (Arduino, via uc2_misc.h C++ branch) → `uc2_random()` (C branch already exists).
- `Adafruit_*` member calls (~50 sites) → new `led_strip_c` shim (below).
- `DeviceRouter::handleLedAct` (C++, called in circle_changed_event) → new
  `extern "C" cJSON *device_router_handle_led_act_c(cJSON *)` wrapper in DeviceRouter.cpp.
- Header `LedController.h` → C: drop Adafruit includes (move into shim), drop the
  header-scope `static Adafruit_* *matrix` (strip handle becomes shim-internal),
  keep C enums + `LedCommand`, declare `led_*` funcs under `extern "C"` guard.

### New shim: `led/led_strip_c.{h,cpp}` (C++ impl, C API — signal_neopixel_c pattern)
Owns the `Adafruit_NeoPixel/DotStar/Protomatter` instance + Ws2812Rmt show-routing:
`led_strip_create(is_status_led)` (variant via DOTSTAR/HUB75 defines, RMT channel logic
moves here), `led_strip_begin`, `led_strip_show` (USE_FASTACCEL→ws2812_rmt_show,
else matrix->show), `led_strip_set_pixel`, `led_strip_fill` (HUB75: fillScreen),
`led_strip_clear` (HUB75: fillScreen(0)), `led_strip_draw_pixel(x,y,rgb565)` (HUB75),
`led_strip_set_brightness`, `led_strip_color`, `led_strip_color_hsv`, `led_strip_gamma32`,
`led_strip_color565` (HUB75; replaces LedController::rgb565), `led_strip_pixels()` (for RMT).
