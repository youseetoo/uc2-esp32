# T5.4 — M5GFX boards: port to IDF as C++ leaves (D4)

**Phase 5 · Effort 1–2 w · Depends: T4.7 · Gated by: D4**
**D4 confirmed 2026-10-08 (T0.1): port the M5GFX trio to IDF — NO env stays on PIO.**
**Invariants:** IDF-only (no PIO); size ±10 % per board. Index: `../PORT_PLAN_STEPS.md`

## Goal
Port the three M5GFX envs (`m5stack_dial`, `m5stack_dial7`, `waveshare_d7`) to IDF as
documented C++ leaves (M5GFX + M5Unified + M5Dial) and record `DOCS/m5gfx.md`.

## Context
- M5GFX is the display stack for M5Stack/7"-class hardware; it supports IDF builds.
- Per D2 the codebase is C with a small frozen C++-leaf set; M5GFX + M5Unified + M5Dial
  join that set (recorded in `DOCS/cpp-leaves.md`, T5.5).
- The dial *controller* (`uc2_dial`) is M5GFX-free (T4.7) and works in `canopen_master`
  (T3.5); this task ports the *display* envs.
- Pins/feature sets: `refs/env-app-mapping.md` rows for the 3 envs;
  `main/config/{m5stack_dial,waveshare_esp32s3_7inchScreen}/PinConfig.h` → `boards/<app>/`.

## Actions
1. Add the three M5GFX apps to `apps/` (one per env) + `boards/<app>/PinConfig.h`.
2. Vendor M5GFX + M5Unified + M5Dial as C++ leaf components (upstream/ ref copy per the D2
   convention) with the IDF display backend (esp_lcd / SPI / i80) wired per board.
3. Per board: build, flash, `[HW]` display smoke (boot logo + dial/7" UI), size within ±10 %
   of `DOCS/baselines.md`.
4. Record `DOCS/m5gfx.md`: versions pinned, backend per board, size deltas, known issues,
   board status (the reference for the T6.1 cutover checklists).
5. CI: `idf-build` matrix += the 3 apps (T6.1 wave).

## Acceptance
- 3 apps build under IDF (no PIO anywhere); `[HW]` smoke passed per board; `DOCS/m5gfx.md`
  complete; sizes within ±10 %.

## Rollback
Per-board revert (apps/ + vendor components are additive).
