# T1.9 — Split `main/src/` into per-controller components (for app-sharing)

**Phase 1 (post-T1.8) · Effort 1–2 d · Depends: T1.6 · Gates: T2.1 (first app that shares components)**
**Invariants:** IDF-only (no PIO); size ±10 %. Index: `../PORT_PLAN_STEPS.md` · Layout: `../refs/component-layout.md`

## Why
T1.6 got the laser app green with an **app-local `uc2_modules`** component that compiles the
TUs straight from `main/src/` (via `INCLUDE_DIRS = main/ + main/src/<module>/`). That works for
**one** app, but every app would carry its own `uc2_modules` (duplicate compiles of the same
modules). Before T2.1 (2nd app) we split `main/src/` into the **top-level per-controller
components** from `refs/component-layout.md` (`uc2_core`, `uc2_serial`, `uc2_canopen`, `uc2_io`,
…), so **all apps share them** and each app's CMakeLists is just a `REQUIRES` list.

## The copy recipe (how to make "copy modules" clean)

**The blocker is includes.** Module files use two include styles:
- **Bare** for the glue headers: `#include "cJsonTool.h"`, `#include "JsonKeys.h"` (glue lives in
  `components/uc2_app/`).
- **Relative** for sibling module headers: `#include "../config/ConfigController.h"` — assumes all
  modules are siblings under ONE root (`main/src/`).

A per-controller split breaks the **cross-component** relative includes (e.g. `State` in `uc2_core`
including `../serial/…` which moves to `uc2_serial`).

**Recipe (minimal source churn):**
1. **Copy `main/src/<module>/` → `components/uc2_<comp>/<module>/`** — PRESERVE the `<module>/`
   subdirectory. Within a component the relative includes keep working (`../config/ConfigController.h`
   from `uc2_core/state/` → `uc2_core/config/ConfigController.h`).
2. **Rewrite CROSS-component relative includes to bare:** `#include "../serial/SerialProcess.h"` →
   `#include "SerialProcess.h"`. Only the cross-component ones (within-component relative includes
   are left alone). `git grep -nE '#include "\.\./[a-z]+/' components/` lists the relative includes;
   fix only the ones whose target module lands in a DIFFERENT component.
3. **Add every component dir to the include path** so bare includes resolve. In the app (or a shared
   helper component), list `${CMAKE_SOURCE_DIR}/components/uc2_core`, `uc2_serial`, `uc2_canopen`,
   `uc2_io`, `uc2_app`, `uc2_led`, … in `INCLUDE_DIRS` / `REQUIRES`.
4. **Per-component CMakeLists** gate sources on Kconfig, mirroring `main/CMakeLists.txt` exactly
   (see `refs/component-layout.md` §3). `uc2_canopen`/`uc2_app` always register (DeviceRouter/
   RoutingTable + core chain compile for every app, same as today).

**Module → component map (laser-relevant subset; finalize per board as needed):**
| modules (`main/src/…`) | component |
|---|---|
| state, config, qid, message, buzzer | `uc2_core` |
| serial | `uc2_serial` |
| canopen | `uc2_canopen` |
| digitalin, digitalout, laser, analogin, analogout, encoder | `uc2_io` |

(`laser` lands in `uc2_io` — it is a digital-output device; give it its own `uc2_laser` only if it
grows.)

**Do NOT delete `main/src/` yet** — it is the source of truth until T6.5. The components are copies;
`main/src/` stays (PIO reference build + the app-local `uc2_modules` fallback).
