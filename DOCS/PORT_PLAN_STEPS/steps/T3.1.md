**Phase 3 · Effort 1 d · Depends: T2.13 · Gated by: —**
**Invariants:** IDF-only (no PIO); RAM band vs baselines. Index: `../PORT_PLAN_STEPS.md`

## Goal
Know exactly what the BT surface is and how much internal RAM the PIO binaries actually
have left — the numbers that decide the T3.2 stack choice.

## Actions
1. **Inventory**: list every BT/PS4 API usage in `main/` — `BtController` (BtController.cpp
   34 KB), `HidController` (19 KB), `esp_hid_gap.c` (30 KB, already C), PSController lib
   usage, HID report formats (DS4 gamepad + trackpad), classic vs BLE usage, OTA-over-BT
   (`UC2_CANOPEN_OTA_NO_RECEIVER/NO_SENDER` semantics). Result → `DOCS/bt-inventory.md`.
2. **`[HW]` RAM baseline**: for each BT board (UC2_2/3/4/WEMOS/canopen_master/
   canopen_standalone_v4) record from the PIO binary: internal DRAM used/free (not PSRAM),
   plus a PS4-connected soak (worst case) — append to `DOCS/baselines.md`.
3. Note the `UC2_FORCE_BT_CLASSIC_ONLY` envs (master, standalone_v4) — classic-only is
   already the field default for the RAM-tightest boards.
